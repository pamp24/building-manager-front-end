1. Executive Summary

The Building Manager application is a full-featured Property & Building Management SaaS platform built on top of the Mantis Angular Dashboard Template by CodedThemes. It serves as a comprehensive digital solution for managing residential and commercial buildings, enabling property owners, property managers, building managers, residents, and administrators to collaborate through a unified interface.

Business Domain: Property Technology (PropTech) — Building & Community Management
Target Market: Building owners, property management companies, residential communities, commercial property managers
Delivery Model: Single-page application (SPA) served via Docker/Nginx with REST API backend

The application implements role-based access control with eight distinct user roles, supports five languages (Greek, English, French, Romanian, Chinese), and integrates 27 backend API services covering authentication, building management, expense statements, payments, support tickets, professional directories, polls, and more.

Key Business Capabilities

  • Building & Apartment Management — CRUD operations for buildings, apartments, and members
  • Common Expense Statements — Create, allocate, and track shared building expenses
  • Payment Processing — Track payments, balances, and collection rates per building
  • Support Ticket System — Issue reporting, assignment, and resolution workflow
  • Professional Directory — Searchable marketplace for property-related service providers
  • Community Features — Polls, calendar events, announcements, chat
  • Role-Specific Dashboards — Tailored analytics for admin, PM, building manager, and user
  • Theme Customization — White-label ready with extensive UI theming options

Current Development Stage

The application appears to be in late-stage development or early production. Core functionality is implemented across all major modules, with unit tests for key authentication and support ticket pages. The project uses a pre-release version of Angular (20.0.0-next.8) and includes both unit testing (Jasmine/Karma) and E2E testing (Playwright) frameworks.

4.4 Data Flow Pattern

The application follows a unidirectional data flow pattern:

  1. User Action → Component event handler
  2. Service Call → HTTP request via Angular HttpClient
  3. Interceptor → JWT token injection via BasicAuthInterceptor/JwtInterceptor
  4. API Response → Observable stream returned to component
  5. State Update → Component updates local state or service-based state
  6. View Update → Angular change detection re-renders the template

6.2 Core Business Flow: Common Expense Statement

The expense statement module is the central business feature of the application:

  1. Building Manager creates a new statement (monthly/periodic expense allocation)
  2. System allocates expenses across building apartments based on defined rules
  3. Notifications are sent to residents/owners about the new statement
  4. Residents/Owners can view their allocated amount and payment status
  5. Payments are tracked per statement, per user, with collection rate monitoring
  6. Building Manager can edit/draft/delete statements as needed
  7. Dashboards display collection rates, monthly trends, and outstanding balances

6.3 Support Ticket Workflow

  1. Any building member can create a support ticket (issue/complaint)
  2. Tickets are routed to the appropriate agent or building manager
  3. Agents can assign, comment, and update status (open/in-progress/resolved)
  4. Users can track their tickets through the dashboard and inbox views
  5. Notifications keep users informed of ticket updates

7.3 Integration Pattern

All services follow a consistent pattern:

12.2 Security Considerations

  • JWT Storage: Tokens stored in browser storage (localStorage/sessionStorage) which is susceptible to XSS attacks. Consider httpOnly cookies for production.
  • Role Duplication: Role enum defined in two places increases risk of inconsistencies
  • reCAPTCHA: ng-recaptcha is included, suggesting CAPTCHA protection for forms
  • Backend Authorization: The front-end role checks are primarily UX-level; real authorization must be enforced on the backend
⚠ Environment Exposure: The production API URL (https://mock-data-api-nextjs.vercel.app) is compiled into the front-end bundle. Ensure this is acceptable from a security standpoint.

15. Recommendations

15.1 Immediate (Short-Term)

  1. Standardize package manager — Remove either yarn.lock or package-lock.json to avoid dependency conflicts
  2. Consolidate Role enum — Merge role.ts and role.model.ts into a single source of truth
  3. Create README.md — Document setup instructions, architecture, environment variables, and deployment process
  4. Audit jQuery usage — Determine if jQuery is actively used or can be safely removed to reduce bundle size
  5. Standardize API URLs — Refactor all services to use environment.apiUrl instead of hardcoded values

15.2 Medium-Term (1-3 Months)

  1. Expand test coverage — Prioritize unit tests for: expense statements CRUD, payment processing, building & apartment management, user role transitions
  2. Implement E2E tests — Use Playwright for critical user journeys: registration → building creation → statement creation → payment tracking
  3. Add CI/CD pipeline — GitHub Actions workflow for lint → test → build → deploy stages
  4. Migrate to stable Angular — Once Angular 20 reaches stable, migrate the project to eliminate pre-release risk
  5. Remove unused dependencies — Conduct a full audit of the 78 runtime dependencies and remove any unused packages

15.3 Long-Term (3-6 Months)

  1. Evaluate state management — If state complexity grows, consider adopting Angular Signals fully or introducing a lightweight state management solution
  2. Performance optimization — Implement lazy loading for images, consider variable fonts, audit bundle size with source-map-explorer
  3. Accessibility (a11y) — Audit components for WCAG compliance; ensure keyboard navigation and screen reader support
  4. PWA readiness — Evaluate adding service worker for offline capabilities and improved loading performance
  5. Monitoring & analytics — Integrate application performance monitoring (e.g., Sentry, Datadog) for production observability
